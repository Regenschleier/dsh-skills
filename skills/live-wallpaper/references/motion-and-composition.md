# 运镜、遮罩与循环的推导 + 实测数据

日期：2026-11-24
环境：Windows 11、ComfyUI Desktop 0.45.5 自带 venv（Python 3.13.12、PyAV 19.0.2）、`libx264` 可用。
源图：832×1248 PNG（Krea2 出图 `overload_set/sc3_s20261504_00001_.png` 的同内容副本）。
产物：3840×2160、24 fps、480 帧（20 s）、13.9 MB MP4。

## 一、为什么不用 i2v

| 模型 | 体积 | 结论 |
|---|---|---|
| `minimax_h3_fl2va_pruned_int8_convrot` | 19.53 GB | 8 GB 显存装不下 |
| `minimax_h3_ref2va_pruned_int8_convrot` | 19.53 GB | 同上 |
| `minimax_h3_fl2va_hyperflow_flash_14b-Q4_K_M.gguf` | 8.43 GB | 勉强加载，但 4K 输出 + 20 s 时长不现实 |

本机 GPU 实测显存 8151 MiB、系统内存 15.8 GB。判定：走程序化 2.5D。

## 二、遮罩：为什么 rx 必须 < 0.5

遮罩用归一化坐标：`nx = (x/W - cx) / rx`，`ny = (y/H - cy) / ry`，`r = sqrt(nx²+ny²)`。
图片左右边界处 `nx = ±0.5/rx`。

- `rx = 0.62` → 边界 `r = 0.806`，落在衰减区，alpha ≈ 73 → **左右各一条竖直硬边**（实测图 `examples/fail-panel-seam.jpg`）。
- `rx = 0.78` → 边界 `r = 0.641`，alpha ≈ 247 → 边界几乎全不透明，等于没羽化。
- `rx = 0.52` → 边界 `r = 0.962`，alpha ≈ 4 → 真正淡出。

纵向同理，但要考虑主体比画布矮（0.99H），上下边界离得远，`ry = 0.57` 已足够。

**平台半径**（plateau，alpha 满值区）决定「脸上有多清晰」：0.34 太糊（只有脸中心实）、0.46 合适、>0.55 又会碰边界。

## 三、亮度匹配

第一次做法把背景压到 ×0.72，遮罩虽然平滑，但明暗台阶把矩形轮廓勾了出来——人眼对**亮度不连续**比对**清晰度不连续**敏感得多。
改法：背景只 ×0.86，压暗统一交给最后一道全局 vignette（`1 - 0.42·r²`，中心亮、四角暗），两层一起压，台阶消失。

## 四、光晕的方形边

光晕贴图 1600×1600，同心椭圆半径若取到 800 以上（原写法 `r = 40 + i*32`，i 到 24 时为 808），会在贴图内部被裁断，alpha 在边界仍是正值 → 合成后出现**一块方形亮斑**。
改法：`r = 30 + i*27`（最大 702），再 `GaussianBlur(90)`，边界 alpha 归零。

## 五、循环闭合

所有相位都写成 `ph = 2π·(frame / N)`：

- 主体缩放 `1.0 + 0.022·sin(ph)`，首末帧同为 1.0；
- 主体位移 `9·sin(ph+0.4)`、`11·sin(ph+1.7)`，正弦在 0 与 2π 同值；
- 床层位移 `26·sin(ph)`、`14·sin(ph+0.8)`；
- 雪花 `x = (x0 + drift·SECONDS·t) % W`、`y = (y0 + speed·SECONDS·t) % (H+200) - 100`，取模天然闭合；
- 光晕 `sin(ph)` 取 6 档之一。

解码首帧与末帧，`ImageChops.difference` 的灰度均值 **1.37/255**（阈值定 3）。

## 七、失败对照表

| 现象 | 直接原因 | 改法 |
|---|---|---|
| 主体像贴上去的矩形 | 遮罩半径 ≥0.5，边界 alpha 未归零 | rx 0.52 / ry 0.57 |
| 矩形轮廓仍在但边是软的 | 背景被单独压暗，亮度台阶 | 背景 ×0.86 + 全局 vignette |
| 右上角一块方形亮斑 | 光晕椭圆半径超过贴图半宽，边界处被裁 | 半径上限 702 + 模糊 90 |
| 左边一片纯黑 | cover 缩放不足，裁切窗口超出图外 | `cover = max(W/sw, H/sh) × 1.06` |
| 首尾帧对不上 | 用了线性动效或最后一帧回退 | 全部改 `2π·t` 周期函数 |
