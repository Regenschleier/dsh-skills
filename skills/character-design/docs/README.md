# 角色设计 skill · 零基础使用手册

> 读者假设：你没写过提示词，也没用过 ComfyUI。每一节都会先讲「这是在干什么」，再讲怎么做。
> 版本：2026-11-16 ｜ 对应 skill：`character-design`

---

## 1. 这是什么

一句话：**它是一套把「我想要这种感觉」翻译成可复制提示词的固定流程**，专门用来出「半写实 3D CG 的日系少女」这种人物图。

它帮你做三件事：

1. 判断你要的到底是 CG、照片，还是暗调纪实——**这三种画法互相冲突，选错一次全白跑**；
2. 给出八段固定顺序的提示词骨架，每段管一件事，坏了知道改哪段；
3. 给一张「症状 → 病因 → 改哪段」的对照表，不用从头重写。

它不做什么：不替你判断「好不好看」；不生成视频；不保证一次就中——它保证的是**每次失败都知道为什么**。

## 2. 前置条件

你需要在装着 ComfyUI 的机器上有这些东西。为什么要检查：这套提示词是配着特定模型写的，换了模型词就失效。

| 需要 | 为什么需要 | 怎么确认 |
|---|---|---|
| ComfyUI 0.45 或更新 | 老版本没有 `MiniMaxH3ImageConditioning` 这个节点 | 打开 ComfyUI，看左下角版本号 |
| `minimax_h3_fl2va_pruned_int8_convrot.safetensors` | 出图的主力模型（约 19.5 GB） | 模型目录 `models\diffusion_models` 里能看到 |
| `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | 读提示词的语言模型（约 14.6 GB） | `models\text_encoders` |
| `minimax_h3_video_vae_fp16.safetensors` | 把潜空间还原成图片 | `models\vae` |
| 8 GB 以上显存 | 768×1344、30 步大约要 8 GB | 任务管理器 → 性能 → GPU 专用内存 |
| 至少 3 GB 空闲硬盘 | 模型缓存与输出图 | 我的电脑看 C 盘 |

**这一步的意义**：以上五样缺任何一样，后面的步骤都会在「提交任务」时静默失败——任务排队了但不出图，看日志才发现模型没加载。所以先花一分钟把这五项对上。

## 3. 分步操作

### 第 1 步：确认服务在跑

**在干什么**：ComfyUI 本体是一个本地网页服务，提示词要通过它的接口送进去。
**为什么**：服务没起，后面所有请求都会「连接被拒绝」。

```powershell
Invoke-RestMethod "http://127.0.0.1:8188/system_stats" -TimeoutSec 5 | ConvertTo-Json -Depth 3
```

看到一串 JSON（里面有 `system` 和 `devices`）就算成功。
失败怎么办：报「无法连接」→ 打开 ComfyUI 桌面版，等界面出来再试；报超时 → 换 `8188` 为你实际的端口（ComfyUI 窗口标题旁边能看到）。

### 第 2 步：先决定画法（这一步决定后面所有词）

**在干什么**：在「CG / 照片 / 暗调纪实」里选一个。
**为什么**：瓷面词和胶片颗粒词会互相打架，模型会二选一，结果通常是「恐怖谷」那种既不像人也不像 CG 的脸。

判断方法：
- 用户说「2.5D」「动漫脸」「日系少女」→ 走 **CG**；
- 用户说「照这张照片」→ 走 **参考图 + CG 措辞**；
- 用户说「纪实」「莫兰迪」「胶片」→ 走 **暗调**，并删掉所有瓷面词。

### 第 3 步：写渲染锚（第一句）

**在干什么**：告诉模型「这是一张什么介质的东西」。
**为什么**：这一句的权重最高，它决定后面所有材质词往哪个方向解释。

```
A still from a Japanese 3D animated feature film, a CG-rendered character with
semi-realistic materials, never a photograph of a real person and never flat
two-dimensional anime artwork.
```

失败怎么查：出图是真人照片 → 检查这句是否在第一段，以及有没有多余的 `photographic / pores`；出图是平涂动漫 → 这句没生效，通常是被后面的「成熟脸」词顶掉了。

### 第 4 步：按八段骨架填

**在干什么**：人物 → 服装 → 景别与动作 → 光 → 配色 → 镜头景深 → 构图气质 → 禁止项。
**为什么**：这八段是按「模型先想谁、再想穿什么、再想怎么拍」的注意顺序排的；打乱顺序，模型会把景别和服装混在一起，出现「脸很小、衣服很大」这种构图。

直接抄模板：[../references/prompt-skeleton.md](../references/prompt-skeleton.md)，把方括号里的内容换掉。

**每段必须写「可判定的状态」**：不写「推近一点」，写「头像在画幅里从 55% 变 65%」；不写「很糊」，写「前景完全失焦成大散景块」。原因是这类蒸馏模型听不懂物理量，但听得懂画面上量得出来的东西。

### 第 5 步：设参数

**在干什么**：定尺寸、步数、权重、种子。

| 参数 | 值 | 为什么 |
|---|---|---|
| 尺寸 | 768×1344 | 32 的倍数；竖幅人像；再大显存不够 |
| 步数 | 30 | 6 步的蒸馏版会把光晕、布纹、发丝细节啃掉 |
| 采样器 | res_multistep | 官方模板默认 |
| cfg | 1（BasicGuider 隐含） | 这类模型不吃高 cfg |
| 种子 | 任意整数 | 想复现就记下来 |

### 第 6 步：看结果，只改一段

**在干什么**：不满意时，先查对照表，只改一段再跑。
**为什么**：一次改三段，出来变好或变坏都不知道是谁的功劳；一次改一段，跑两轮就能定位。

对照表：[../references/failure-table.md](../references/failure-table.md)。

### 第 7 步：归档

**在干什么**：把工作流 JSON 和成图存下来。
**为什么**：下次要「同一张脸换个场景」，靠的是工作流里的种子和参考图，不是靠回忆。

## 4. 为什么是这么做的（原理）

**参考图为什么能把成年脸搬过来**：参考图会以两种方式影响结果——接 vae 时，它被编码成「参考潜空间」，权重非常大，等于告诉模型「就照这张画」；不接 vae 时，它只作为文字模型看的图，权重小，更像「参考一下气质」。

**所以「照片变 CG」的开关其实是那根 vae 线**，不是措辞。措辞只能在「已经是 CG」之后修饰材质。

**为什么换机位要删参考图**：只要图片还接在输入上，视觉 token 就把构图钉在原图那个机位上；写「俯拍」「背后」都拗不过它。

**为什么 6 步会丢细节**：蒸馏模型的训练目标是「用最少步数到差不多」，它优先保住大形和光影关系，先牺牲的是光晕、布纹、发丝这种高频细节。所以光刃、散景这类「细节美」必须 30 步。

## 5. 报错对照表

| 报错原文 | 含义 | 怎么修 |
|---|---|---|
| `got an unexpected keyword argument 'image_0'` | 参考图插槽的键名写错了 | API 格式里必须写 `images.image_0`（**带点**），写成 `image_0` 会被当成参数塞给函数 |
| `net::ERR_CONNECTION_CLOSED` | 目标网站连不上（不是工具坏） | 先开代理；或换镜像站 |
| 任务排队了但一直不出图 | 模型没加载成功 | 看 ComfyUI 控制台第一屏，通常有 `Error loading` |
| `out of memory` | 显存不够 | 尺寸降到 704×1216，或关掉别的占显存的程序 |
| 出图全黑或全灰 | VAE 接错 | 检查 VAEDecode 是否接的是 `minimax_h3_video_vae_fp16` |

## 6. 怎么算成功

四条同时满足才算这张图过关：

1. **介质对**：一眼能看出是 CG 渲染，不是照片，也不是平涂插画；
2. **年龄对**：是成年人，不是小孩；
3. **有生命感**：有具体动作和热源，不是静止空镜；
4. **可用**：没有多余手指、没有第二个人、没有文字水印。

只满足 1、2 而缺 3，用户会说「诡异」；只满足 3、4 而缺 1，用户会说「太丑」。

## 7. 术语表

| 词 | 白话解释 |
|---|---|
| 渲染锚 | 提示词第一句，声明「这是什么介质的东西」 |
| 半写实 3D CG | 游戏 CG／动画电影那种：有材质、有光影，但脸不追求真人 |
| 恐怖谷 | 像人又不是人，看着发毛 |
| 瓷面 | 皮肤像瓷器一样均匀、无毛孔、有一层薄高光 |
| 潜空间 / latent | 模型内部表示图片的那串数字，不是像素 |
| VAE | 潜空间 ↔ 像素 的翻译器 |
| 蒸馏模型 | 把几十步压缩成几步的加速版，代价是细节 |
| 种子 / seed | 决定「这一张」的随机数；同种子同参数才能复现 |
| ComfyUI | 用节点连线搭图像生成流程的软件 |
