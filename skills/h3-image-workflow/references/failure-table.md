# 失败对照表（症状 → 病因 → 改哪）

每一条都在 ComfyUI 0.45.2 + MiniMax H3 int8 fl2va 上实测过。

| # | 症状 | 病因 | 改法 |
|---|---|---|---|
| 1 | 四张「不同机位」的图长得一模一样 | `images` 插槽还接着参考图，构图被视觉 token 钉死 | 删掉 `images.image_0` 整个键；人物改用文字重写 |
| 2 | 断 vae 了构图还是不动 | 只断了 vae，没断 images | 见第 1 条 |
| 3 | 永远是真人照片，怎么写 CG 词都没用 | 节点 6 接着 vae（参考图被锚成 latent reference） | 删掉节点 6 的 `vae`；`VAEDecode` 的 vae 保留 |
| 4 | 报 `execute() got an unexpected keyword argument 'image_0'` | autogrow 槽位键没写点号前缀 | 写成 `"images.image_0"` |
| 5 | 报 `Required input is missing: images` | 删键时删过头，或键名拼错 | 只删 `images.image_0` 这一条 |
| 6 | 换机位后又回到上一张的动作 | 提示词残留 `stomp / kick / sneaker the largest` | 动作段整段重写，只留新机位需要的描述 |
| 7 | 出图 1.8 MP、显存吃满或中断 | `width/height` 留 0，按参考图短边 1024 自动算画布 | 显式 768×1344 |
| 8 | 下颌变方、双下巴感 | 参考图是低机位仰拍，机位被一起搬过来 | 裁成目标比例，或在提示词里明写机位高度 |
| 9 | 脸挺好但「像假人」 | 瓷面 + 玻璃眼 + 灰色环境同时出现 | 加「有生命的皮肤」措辞 + 一个具体动作 + 一处暖光源 |
| 10 | 细节被对称化（单侧颜料痕变双侧） | 模型默认补全 | 单开一段点名另一侧干净 |
| 11 | 光斑、光刃、雾都没有 | 用了 6 步 HyperFlow 蒸馏 | 换 30 步 int8；仍不出就后期加 |
| 12 | 参考图是照片，结果也全是照片 | 想 CG 却拿照片当参考且接着 vae | CG 进 CG 出：先出 CG，再拿 CG 当参考 |

## 判断顺序（30 秒定位）

1. 看**构图**错 → 先查 images 插槽。
2. 看**质感**错（照片 / CG）→ 再查 vae。
3. 看**机位被旧动作拉回** → 查提示词里的残留动作词。
4. 看**细节错**（对称化、少一件）→ 查有没有单开一段点名。
5. 都对了但「不好看」→ 那是审美问题，回 `character-design` 的八段骨架改措辞。
